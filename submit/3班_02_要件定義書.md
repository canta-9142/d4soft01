# 要件定義書

## 1. システムの概要

- 本システムは、タスクをカードとして二次元のキャンバス上に自由に配置し、有向の線で結ぶキャンバス型ToDoアプリである。
- タスクのタイトル、説明文、ステータス、位置を管理し、親子関係、依存関係、作業の流れなどを視覚的に表現する。
- 従来は属性や並び順で表していた関係を全面的に線で示し、タスク網の構造を一瞥で把握可能にする。
- 複数のキャンバスを用途ごとに使い分け、検索、ステータス絞り込み、および基準タスクからの最短距離による深さフィルターで必要な範囲に集中できる。
- 授業課題、個人開発、イベント準備や、既存プロジェクトから抜き出したタスク群の整理・説明を主な利用場面とし、キーボード中心の素早い連続操作によって、思考を中断せずタスク網を構築・編集できることを目的とする。

## 2. 制約・前提

- 実装はHTML、Tailwind CSSを含むCSS、TypeScriptを用い、ビルド済みの静的ファイルをHTTPサーバーから配信してブラウザ上で動作させる。
- `file://`による直接実行は対象外とする。
- データは外部サーバーへ送信せず、手動保存時またはキャンバス切り替え時に、同一ブラウザー内のlocalStorageへJSON形式で保存するため、別端末との同期やクラウド共有は前提としない。
- タスクと接続は所属キャンバス内でのみ管理し、キャンバスを越えた接続は行わない。
- 接続は必ず向きを持つが、矢印が示す業務上の意味は固定しない。
- キャンバスがない初期状態ではタスク操作や検索などはできず、先にキャンバスを作成する。
- タスクのタイトルとキャンバス名は必須とし、空欄または空白のみの値を許可しない。

## 3. 機能要件

- 利用者はキャンバスの作成、切り替え、名称変更、パン移動、削除を行える。
- 各キャンバスでは、タイトル、説明文、3段階のステータスを持つタスクの登録・選択・編集・移動・コピー・貼り付け・削除を行う。
- 接続モードでは2つの異なる表示中タスクを順に選び、親から子への接続を作成し、接続線単位で削除できる。
- 同一方向の重複と自己接続は禁止し、逆向接続と循環は許容する。
- タイトル・説明文の部分一致検索、ステータス絞り込み、選択タスクを基準とした深さフィルターは併用でき、全条件を満たすタスクとその両端が表示される接続線のみを描画する。
- 主要操作はマウスとショートカットキーで実行でき、対象操作を最大50件まで取り消し・やり直しできる。
- 状態は利用者の指示またはキャンバス切り替え時に保存し、起動時または利用者の指示で復元する。

## 4. 非機能要件

- キー入力、タスクの作成・移動、接続の更新、検索条件の変更は速やかに画面へ反映し、連続する入力や思考を妨げない応答性を確保する。
- 頻繁な操作の手順とキー配置を一貫させ、現在のモード、選択中のタスクや接続、検索・深さフィルター、未保存状態を常に判別可能にする。
- 選択や操作状態は色のみに依存せず、文字、線幅、表示サイズ等も用いて区別する。
- 不正な入力や保存データ、localStorageへの書き込み失敗があってもアプリを停止させず、短いエラー表示を行い、既存の保存データを上書き・破棄しない。
- 復元時は必須項目、型、ID参照、座標値等を検証する。
- さらに、ユーザー入力をHTMLとして解釈せずテキストで描画し、入力内容を外部へ送信しない。
