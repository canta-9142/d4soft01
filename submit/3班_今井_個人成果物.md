## application と domain・各種サービスの連携

- Application はユースケースの窓口であり、キャンバス／タスク／接続の作成・更新・削除、フィルター、保存・復元、Undo/Redoを受け持ちます。`src/application/application.ts`
- 永続化する状態は AppState に集約し、Canvas が Task と Connection を所有します。一方、選択中のタスク・接続、接続途中の親タスク、クリップボード、履歴などの一時状態は Application 側だけに保持することとしています。`src/application/app-state.ts`
- FilterService は状態を変更しない純粋な絞り込み処理として分離しています。検索・ステータス・深さをまとめて適用し、表示対象外のタスクにつながる接続線も除外するため、表示の整合性を保てます。`src/services/filter-service.ts`
- LocalStorageService は保存用のスナップショット化、バリデーション、ドメインオブジェクトへの復元を担当しています。`src/services/local-storage-service.ts`
- 履歴は HistoryManager に分離し、削除時の関連接続や選択状態までスナップショットとして扱います。復元時には履歴・クリップボードなどの一時状態を初期化します。`src/history/history-manager.ts`

## events・renderer と application の連携

- `src/main.ts:5` で Application を1つ生成し、同じインスタンスを EventController と Renderer に渡しています。起動時は復元 → イベント登録 → 描画の順です。
- EventController ではDOMイベントをアプリ操作へ翻訳しています。クリック、フォーム、ポインタ、右クリック、キーボード操作から Application のメソッドを呼び、成功・失敗に応じて Renderer へ再描画やメッセージ表示を依頼します。`src/ui/events.ts`
- Renderer は状態変更を行わず、Application の状態からDOMとSVGを描画します。タスクカードと接続線を別レイヤーにし、可視タスク・可視接続のみを描画します。`src/ui/renderer.ts:100`
- 接続線はカードの実寸から中心座標を計算してSVGで描画するため、カードサイズに追従します。選択状態や矢印も同じ描画処理にまとめられています。
- ドラッグ中は毎回全画面を再描画せず、対象カードの位置と接続線だけを即時更新します。ドラッグ完了時にだけ未保存状態更新と履歴登録、全体再描画を行うため、操作感と履歴粒度を両立しています。
- Pointer Capture をカード自身に設定し、選択時にカードDOMを置き換えないようにしています。これにより、ドラッグ後のダブルクリックが「空白キャンバスのダブルクリック」と誤認されないよう配慮されています。
- モード（通常・編集中・接続中）に応じて操作ボタンを無効化し、接続元の選択などもUIに反映します。画面上で実行できない操作を抑制しつつ、Application 側でも入力値や重複接続を検証する二重の安全策になっています。

EventController および Renderer のみにDOM操作を押しやることで、Application へのモジュール追加を容易にしています。
分担として、他3名に任せる箇所が FilterService などのロジック側の実装のみに限定したため、UI側とロジック側を疎結合とするこのような設計になりました。

## CSSなどのデザイン上の工夫

- タスクと接続関係が主役になるよう、背景・カード・メニューは白と薄いグレーを中心にし、青色は主要ボタン、選択状態、フォーカス、接続モードなど注目が必要な箇所に限定しました。画面全体を落ち着いた配色にすることで、現在の操作対象を見つけやすくしています。`style.css`
- タスクカードは、通常・ホバー・選択中・接続元・編集中の状態ごとに、枠線、影、サイズ、ラベルを変えています。また、説明文は通常時には隠し、ホバー時または選択時にだけ表示することで、一覧性と詳細確認のしやすさを両立しました。
- ステータスは文字だけでなく色とバッジでも区別し、「進行中」は黄色系、「完了」は緑色系で表示しています。完了タスクのタイトルには薄い文字色と取り消し線も加え、色だけに頼らず状態を判断できるようにしました。
- キャンバス背景には24px間隔のグリッドを敷き、タスクを配置する作業領域であることを視覚的に示しました。キャンバス移動中はカーソルを `grab` から `grabbing` に変え、操作が受け付けられていることも分かるようにしています。
- 接続線はカードより控えめなグレーにし、選択時のみ青色かつ太い線へ変化させています。さらに、見た目の線とは別に透明で幅の広いクリック領域を設け、細い線でも選択しやすくしています。
- ボタン、入力欄、メニュー、ダイアログで角丸・境界線・余白をそろえ、共通した操作感を持たせました。ホバー、フォーカス、無効状態、エラー表示もそれぞれ見た目を変え、操作可能かどうかや入力結果がすぐ伝わるようにしています。
- 操作一覧はキーボードのキーを `kbd` 要素でキーキャップ風に表示し、内容をカード状に整理しました。背景の暗転とぼかし、閉じるボタンのフォーカス表示も加え、キャンバスと説明画面の区切りを明確にしています。
- 画面幅に応じてメニューバーを2段にし、操作一覧を2列から1列へ変更するレスポンシブ対応を行いました。小さい画面では一部の補助情報を隠し、ボタンの間隔や文字サイズも調整することで、主要操作を残しながら画面内に収まるようにしています。
- HTML側では配置や余白などの調整にTailwind CSSのユーティリティクラスを使い、状態に応じた見た目や再利用する部品のスタイルは `style.css` にまとめました。役割を分けることで、レイアウト調整とコンポーネントの状態表現を管理しやすくしています。`index.html` `src/tailwind.css`
